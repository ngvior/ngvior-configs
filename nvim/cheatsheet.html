How to read a binding

<C-o>means ctrl + o — never the angle brackets
<S-h>means shift + h, i.e. capital H
<M-j>means alt + j (M is for Meta)
<CR>means enter
leaderis the space bar in this config
gdtwo keycaps side by side means press in sequence, not together

Navigation pairs live on the brackets. ]x / [x, as in :help and every tutorial. On the latam layout they need Shift. Brace aliases (}x / {x) used to save that modifier, but they turned { and } into prefixes, which delayed paragraph motion by timeoutlen. A key cannot be a complete mapping and a prefix at once without waiting, so the aliases were removed.

The one habit worth building: press space and wait. which-key lists every group. You do not have to memorise this page — it is here for the twenty keys you use every hour.

Normal mode is home. Every key is a command there. You visit insert mode to type, then esc straight back. If a key does something strange, you are probably in the wrong mode — press esc.

Shift+arrow selects without leaving insert. keymodel = "startsel,stopsel" (options.lua) makes Shift+arrow start a visual selection while in insert mode; y/d/c act on it and drop you back in insert. Replaces insert mode's defaults for Shift+Left/Right (word jump, still on Ctrl+←/→) and Shift+Up/Down (page scroll).

Undo & rescue

uUndo — this is your ctrl+z
<C-r>Redo
UUndo every change on the last touched line
leadersuUndotree — browse the whole undo history visually
:earlier 10mRewind the buffer to how it looked 10 minutes ago
:later 5mFast-forward again
:e!Reload from disk, throwing away every unsaved change
leaderghrReset the hunk under the cursor to its git state
leaderghRReset the whole buffer to its git state

Ctrl+Z does not undo. In a terminal it suspends nvim and drops you back to the shell. If nvim seems to vanish, type fg to get it back.

Save & quit

<C-s>Save
:wWrite (save)
:qQuit the window — refuses if there are unsaved changes
:wqSave and quit
:q!Quit, discarding unsaved changes
leaderqqQuit everything
leaderbdClose this buffer, keep the window layout
leaderfsSave as — prompts for a path (tab completes) and renames the buffer
:sav pathSame, by hand — writes the file and names the buffer

An unnamed buffer will not :w. leaderfn opens an empty, anonymous buffer. Use leaderfs or :sav path, not :w path — that writes the contents but leaves the buffer unnamed, so the next :w fails again. leaderfs also creates the parent directory and never overwrites an existing file.

Autoformat is on. Saving runs the formatter. That is how a file you only opened ends up with a diff. leaderuf toggles it globally, leaderuF for this buffer only.

Jump historythe big one

<C-o>Back to where you jumped from — across files
<C-i>Forward again
``Back to the exact position before the last jump
<C-^>Toggle between the two most recent buffers
leadersjBrowse the whole jump list

This is the key that makes nvim feel navigable. Jump to a definition, read it, <C-o> and you are back exactly where you were. It is VSCode's alt+← but it works through files, searches and greps alike.

Edit text

dwDelete to the end of the word
ddDelete the whole line

The grammar: verb + object. d delete, c change, y yank. w word, iw inside word, i" inside quotes, ap a paragraph. Any verb combines with any object — that is the whole trick.

Deleting copies. dd puts the line in the register, so it is a cut, not a delete. That is why pasting after deleting works.

leaderghb vs leadergb. Two different plugins. ghb (gitsigns) shows the current line's blame in a popup, on demand. gb (git-blame.nvim) toggles a permanent blame pinned to the end of every line, and starts disabled (enabled = false).

Copilot

<M-l>Accept the ghost-text suggestion
<M-}>/<M-{>Cycle to the next / previous suggestion
<M-c>Dismiss the suggestion
leaderaaCopilotChat in a floating window
leaderaeCopilotChat: explain the selected code

The completion menu. It opens by itself as you type. <C-n> forces it open (and moves down once open), <C-p> moves up, <CR> accepts, <C-e> closes it, <C-k> shows the signature. blink's own default for forcing it open is <C-space>, but that is herdr's prefix — it never reaches nvim inside herdr, which is why it lives on <C-n> here. Same reason treesitter's grow-selection moved to <M-e>.

Ghost text, not a menu. Copilot suggests inline in grey as you type; <M-l> takes it. It deliberately stays out of the blink.cmp menu, which is reserved for the LSP. Chat lives under leadera because leaderc is LazyVim's code group.

Braces, not brackets. Cycling uses <M-{> and <M-}> rather than copilot's default <M-[> / <M-]>: on the es-latam layout the braces are the unshifted characters, so the defaults would cost an extra Shift every time.

Windows & splits

leader|Split vertically (side by side)
leader-Split horizontally (one above the other)
<C-h><C-j><C-k><C-l>Move focus left / down / up / right
<C-↑><C-↓><C-←><C-→>Resize the focused window
leaderwdClose this window
<C-w>Window hydra — hold it and keep pressing to resize and move

Three alt keys are contested. nvim uses <M-j> / <M-k> to move a line and <M-l> to accept a Copilot suggestion, while herdr uses the same alt+j / k / l to move between panes. With a single pane they appear to work. Split with alt+v and retest before trusting them; herdr also answers on prefix+hjkl.

Splits vs herdr panes. These split inside nvim and share its LSP and buffers. herdr's alt+v splits the terminal itself. Same idea, different level — use nvim splits for code, herdr panes for separate programs.

Terminallike VSCode

<M-t>Toggle a terminal at the bottom — press again to hide it
leaderftSame terminal, at the project root
leaderfTTerminal at the current file's directory
escescTerminal mode → normal mode, so you can scroll and yank
qHide the terminal (from normal mode, after the double esc)
iBack into terminal mode, to type again
gfOpen the file under the cursor — works on stack traces
<C-\><C-n>The always-works escape from any terminal, including :terminal

The two modes are the whole trick. A terminal buffer starts in terminal mode, where every key goes to the shell — that is why you could not get out. Double esc puts you in normal mode, where the buffer behaves like any other file: jk scroll, y yanks, / searches. i goes back in.

Why not <C-/>. That is LazyVim's default and it is still mapped, but on the latam layout / is shift+7, so ctrl+/ is really ctrl+shift+7 and the terminal never sends the ^_ byte nvim is waiting for. <M-t> is an alias to the same toggle.

Prefer this over :terminal. The bare :terminal command opens a plain buffer with none of these keys — no q, no gf, no toggle. The double esc does work there now, but everything else is missing.

Traps worth knowing

ctrl+zSuspends nvim to the background. fg brings it back — it is not undo
sIs Flash here, not substitute. Use cl for the old behaviour
:wRuns the formatter. An untouched file can still end up with a diff
leadereToggles the tree — from a file it closes it. Use <C-h> to focus it instead
}Jumps to the next BLANK line, not the next block. Two blank lines in a row take two presses
<C-i>Is the same byte as tab — rebinding one rebinds the other
E139The file is already in another buffer, maybe hidden. :ls! to find it, :bwipeout <n> to free it
:w pathOn an unnamed buffer it writes but does not name it. Use leaderfs
escWhen lost, press it twice. Then u to undo whatever happened

Nothing matches that. esc to clear.
